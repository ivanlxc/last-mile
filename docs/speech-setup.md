# English speech

Speech is optional. Gameplay, typed advisor questions and written reports continue to work without Deepgram.

Set `DEEPGRAM_API_KEY` in the ignored project-root `.env` (or the deployment's server environment), then restart the backend. Never put this key in a `VITE_` variable or client bundle. `DEEPGRAM_ENABLED=false` disables both recording and read aloud without deleting the key. No audio, transcript, synthesized text or provider credential is logged or saved by these endpoints.

The game uses the existing session cookie and same-origin server proxy. Local Vite development proxies WebSocket requests as well as HTTP; production connects directly to the same application origin. WebSocket upgrades require an allowed Origin, and cloud requests retain the invitation/player guard. Do not expose an unauthenticated speech proxy.

## Voice input

`GET /api/v1/speech/config` returns availability and limits. `WS /api/v1/speech/transcribe` accepts raw PCM16 little-endian mono audio at 16 kHz after `{ "type": "ready" }`. Recording lasts at most 90 seconds. The backend uses Nova-3 with English fixed and emits:

```json
{"type":"transcript","text":"Check the bridge.","isFinal":true,"speechFinal":true,"segmentId":"0:2.4"}
```

`segmentId` is supplied when the provider sends its start/duration timestamps; it identifies repeated delivery of a segment without treating intentionally repeated words as duplicates. Interim text is provisional. Recording does not send an advisor request or execute a game action.

On stop, flush the capture buffer and send `{ "type": "stop" }`, leaving the socket open. The backend sends Deepgram `CloseStream`, forwards its remaining final results (including an empty final segment) and emits `{ "type": "done" }` on clean provider closure. The browser must not immediately close its socket and lose the final phrase. Its automatic stop runs one second before the server's 90-second cap, allowing the final partial audio packet to flush. The server recording window begins at provider readiness; the separate 10-second connection timeout and credential expiry still apply. A provider timeout emits a safe error instead of claiming completion. Disconnecting cancels the upstream connection. Review the editable draft before sending it to the advisor.

## Read aloud

`POST /api/v1/speech/synthesize` accepts only `{ "text": "English text to read" }` (1–2000 characters) and returns `audio/mpeg`. Longer reports should be split at sentence boundaries and played sequentially, including uncertainty and limitations. Audio is generated by Aura-2 Thalia; `DEEPGRAM_TTS_MODEL=aura-2-apollo-en` optionally selects an alternative English voice. The server validates this allowlist; the client cannot select arbitrary models or endpoints. Requests have a 20-second deadline and a 4 MiB response cap.

Use a single browser playback manager and stop playback before recording. Reading a report aloud does not upload it to the advisor or imply that an interrupted report was fully presented. Speech-specific HTTP errors contain `{ "error": { "code": "…", "message": "…" } }`; authentication errors use the existing application problem format.

Rate and concurrency limits are per application instance: voice input allows 1 recording per player, 4 globally, 12 starts per player and 60 globally per 10 minutes; read aloud allows 2 requests per player, 4 globally, 60 starts per player and 240 globally per 10 minutes. Local mode shares a loopback-IP budget. When deploying multiple instances, add a shared quota before treating these bounds as an account-wide cost ceiling.

Protocol tests use an in-process provider double and mocked synthesis; no live provider traffic is required. A real microphone/browser check and a configured Deepgram account are still needed to assess transcription quality and voice latency.

Official API references: [Nova streaming](https://developers.deepgram.com/reference/speech-to-text/listen-streaming), [CloseStream finalization](https://developers.deepgram.com/docs/close-stream), [Aura REST synthesis](https://developers.deepgram.com/docs/text-to-speech), [English voices](https://developers.deepgram.com/docs/tts-models).
