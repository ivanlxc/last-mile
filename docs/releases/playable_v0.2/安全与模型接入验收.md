# 安全与模型接入验收

验收日期：2026-09-16。范围为本机浏览器演示、当前依赖锁文件和当前生产构建；未连接真实付费模型。

## 1. 结论与复现

当前生产资源、开发服务器文件边界和模型配置检查通过。执行：

```sh
pnpm build
pnpm exec vitest run tests/security
pnpm typecheck
pnpm audit --registry=https://registry.npmjs.org --json
```

安全测试为 2 个文件、4 项测试，全部通过。该套测试直接检查 `dist/client`，必须先构建。另有 AI 单元与真实领域事件测试覆盖供应商协议、预算、过期建议、预决策资料和行为规则，位于 `tests/ai`；安全测试不替代这些检查。

### 生产资源

- 遍历全部 `dist/client` 文件，包括 JavaScript、GLB 和图片；禁止服务端目录、源码、数据库、source map 和符号链接。
- 检索隐藏来源 ID、私有 case 字段、剧本文件名、两家模型配置变量、所有尚需调查才能获得的剧本文本及明显密钥格式。当前构建未发现匹配。
- 通过实际 Fastify 静态路由读取每个资源，将响应 SHA-256 与构建文件逐一比较。
- 用普通 JSON 与 HTML 请求分别探测 15 个私有或目录穿越 URL，覆盖 `.env`、`.git`、SQLite、服务端代码、Agent 提示词、完整剧本和编码穿越。未返回私有内容。SPA 路由可能以 200 返回首页，测试要求其字节哈希必须与 `index.html` 相同；不会把“HTTP 200”直接当作泄漏或通过。
- 静态根目录固定为 `dist/client`。隐藏剧情不靠前端隐藏按钮保护，也没有打进生产 JavaScript 后再筛选。

### 开发资源

发现并修复了开发配置原先允许整个仓库被 `/@fs` 访问的问题。当前 `fs.strict` 开启，允许目录收窄为 `client` 和 `node_modules`，并拒绝服务端、设计文档、数据库、环境文件及原始资产归档。

测试启动使用实际 Vite 配置的独立本机临时端口，执行 5 个私有文件路径 × 2 种 `/@fs` 写法 × 普通、`?raw`、`?import` 共 30 次探测；结果为拒绝或精确首页回退，均无私有内容。测试不读取实际 `.env` 文件内容，不输出响应中的秘密值。

服务端仅监听 `127.0.0.1`。HTTP 层另有来源、Host、跨站请求、本机访问和启动 Cookie 验证，相关测试位于 `tests/http`。静态插件拒绝错误现映射为固定的公共 400/403/404 问题对象，不回显底层文件路径错误。

## 2. 真实模型配置

从仓库根目录复制 `.env.example` 为 `.env`。开发和正式启动命令均由 Node 的 `--env-file-if-exists=.env` 读取服务端变量；不要使用 `VITE_` 前缀，不要把密钥放进浏览器代码。

默认不产生模型调用：

```dotenv
MODEL_PROVIDER=offline
```

OpenAI 配置：

```dotenv
MODEL_PROVIDER=openai
OPENAI_API_KEY=在本机填写自己的密钥
OPENAI_MODEL=填写账户可用且支持Structured_Outputs的模型ID
```

Anthropic 配置：

```dotenv
MODEL_PROVIDER=anthropic
ANTHROPIC_API_KEY=在本机填写自己的密钥
ANTHROPIC_MODEL=填写账户可用且支持Structured_Outputs的模型ID
```

这里的中文值是说明性占位符，不能直接用于请求。选定供应商必须同时填写密钥与模型 ID；没有预置收费模型 ID。两家供应商使用相同配置分别服务 Advisor 和 Evaluator。切换后重启服务。

| 项目      | 当前实现                                                                                     |
| --------- | -------------------------------------------------------------------------------------------- |
| OpenAI    | 原生 `fetch` 调用 Responses，`text.format` 为严格 JSON Schema，`store:false`                 |
| Anthropic | 原生 `fetch` 调用 Messages，`output_config.format` 为 JSON Schema，API 版本头为 `2023-06-01` |
| Advisor   | 每次请求 8 秒超时、最多 1,200 输出 token                                                     |
| Evaluator | 每次请求 20 秒超时、最多 3,000 输出 token                                                    |
| 调用预算  | 每个逻辑 job 最多 2 次已发送请求；Advisor 每局最多 30 次，SQLite 持久化计数                  |
| 重试      | 没有 SDK 隐式重试；格式修复和恢复共享剩余调用额度                                            |
| 失败      | 明确显示 `offline_template`；Advisor 不凭模板制造路线推荐                                    |
| 配置检查  | 只检查选定变量是否齐全，不在启动时发模型探活请求                                             |

`modelConfigured=true` 表示配置齐全，不代表密钥、权限或模型 ID 已经经供应商验证。真正开始新场景、上传或提问等会触发模型调用并可能计费；本轮没有执行这些真实调用。选择离线模式仍可完成报告、路线、时钟和规则复盘流程。

供应商支持的 JSON Schema 子集用于限制生成格式，本地仍执行完整契约与引用权限校验；供应商接受结构化输出不等于语义正确。协议依据：[OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)、[Anthropic Structured Outputs](https://platform.claude.com/docs/en/build-with-claude/structured-outputs)、[Anthropic Messages API](https://platform.claude.com/docs/en/api/messages/create)。

## 4. 验收边界

- 本轮验证实际本机构建和本机服务器，不是公网、多用户身份隔离或抗恶意本机进程的安全认证。能读取仓库或 SQLite 的本机账户仍能查看剧本。
- 扫描能发现已知私有字段、来源 ID、剧情文本、密钥格式与目录配置回归，不能证明所有可能的编码或语义泄漏均不存在。新增公开资源应再次构建并测试。
- 真实密钥权限、所选模型兼容性、联网可达性、实际延迟和收费没有经本轮付费调用验证。HTTP 协议测试使用伪服务器响应。
- Advisor 不读取完整私有世界；Evaluator 仅接收封存的行为事实。自然语言可能仍错误理解或表述，引用验证不能证明心理归因正确。四维结果是本局观察，不是经验证的心理量表或人格诊断。
- 当前密钥不会被写入客户端构建或健康响应；服务端环境与本机文件权限仍由运行者管理。`.env` 与本地数据库已被 `.gitignore` 排除。
