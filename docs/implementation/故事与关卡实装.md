# LAST MILE — 第一版完整叙事脚本

版本：0.1 / 2026-09-16。游戏使用虚构的萨赫尔河谷，面向单人指挥官。公开对白在 `client/src/lib/narrative.ts`，真实分支继续由服务器的 v0.5 campaign-reference.json 决定。本文为作者资料，不由静态站点发布。

## 主题与人物

临时停火后的傍晚，一支载有二十名平民的车队，要在十分钟的转运窗口内抵达曙光接收站。玩家面对的不是全知地图，而是有限、过期、相互转述的消息。每一次确认都有机会成本。游戏的中心问题是：你为什么相信一条建议，又知道它依据了什么？

- 指挥官：唯一玩家。决定调查方向、向 AI 传递哪些材料和最终路线。
- 诺亚：情报员，负责地图、卫星与无人机。重视观察范围，不将图像当作完整事实。
- 萨米拉：联络员，负责机构与当地目击者。熟悉流程，关注原始来源和名单交接。
- 医护员：提供乘客状态的系统提示。第八分钟进入需要额外支持的状态；剧本没有死亡事件。
- AI 顾问：整理收到的材料，引用依据、说明缺口、给出有条件的建议。它没有上帝视角，不替玩家下达命令。
- 复盘分析员：独立 Agent，只读取封存后的行为事实；任务结果的叙事解释由另一模块给出。

## 序章：最后一班

画面是一支白色车队沿沙漠边缘的公路驶向暮色中的河谷。广播告知接收窗口；一位乘客收好钥匙，另一位握着证件。所有二十人均已在车上。玩家可在不计时的任务简报中阅读规则、查看沙盘与两位伙伴的能力。按下“开始护送”后计时开始，车队从集结院沿 R00 行进三十秒抵达西门。

教程明确展示：调查额度整局共享；每名岗位每关最多三次上报；每关最多五张正式上传；更正与溯源占新额度；离场取消尚未完成的调查但不返还已经消耗的渠道次数；AI 不会自动看到倒计时、医疗状态和余额。

## 第一幕：门后的答案（E1 / N01）

**登场对白。** 萨米拉：名单在我手上。走主门可以办理登记；绕行的话，这件事还得在后面处理。

**玩家问题。** 历史通畅画面和“应该仍能电子核验”的转述，能否说明当下的登记能力？玩家可以索取简报、花渠道次数获得卫星历史帧、无人机当前观察、机构回应或目击记录。每种报告保留时间、来源与观察边界。

**公开选择。** 主门登记再前进，公开基准六十五秒但可能等待；南侧服务路绕行，一百三十秒，名单补录可能留到后面。

**作者分支。** A：设备工作，主门按基准通过，名单办理完成。B：设备离线，主门额外等待九十秒。两种情况下绕行均不办理名单，车队经 R02、R03 到达市集，形成跨关待办。后果通过行程状态与接下来可见的待办展示，绝不预先给玩家答案。

**教学意图。** 看似清晰的图片也可能回答错了时间点或问题。玩家可以接受不确定性，但需要知道在接受什么。

## 第二幕：回声的重量（E2 / N02）

**登场对白。** 萨米拉：我听到了几种很像的说法。先别把转述的人数，当成亲眼看见的人数。

**玩家问题。** 街巷传来爆响，围绕白色皮卡的多条说法逐步汇集。四条转述实际源于同一位司机；只有在付费溯源并收到结果后，这个关系才对玩家可见，上传相应结果后才对 AI 可见。无人机影像是独立观察，不伪装成同源信息。爆响原因保持未确认，不能把它写成已证实袭击。

**公开选择。** 尝试市集主路，公开基准七十五秒且可能遇阻；通过连接路绕到桥头，一百四十五秒。

**作者分支。** B：一条车道可用，主路按基准到达桥头。A：救援作业占用道路；车队先行至 R04 的四成位置，折返，再经连接路绕行，共二百四十五秒，留下待检查事项。车辆在沙盘上真实前进、折返，不直接瞬移。

**教学意图。** 多个来源标签不必然等于多份独立证据；任务需要的是通行判断，而不是为传闻补出完整惊险故事。

## 第三幕：河的另一边（E3 / N05）

**登场对白。** 诺亚：快到了。请把“桥还在”和“我们的车现在可以通过”分开确认。

**玩家问题。** 影像中的桥体外观、现场的车辆许可、旧河床的通行情况与剩余时间分别回答不同问题。AI 只能分析玩家上传的部分；指挥官需要将看见的材料和自身约束一起考虑。

**公开选择。** 主桥申请通行，公开基准一百零五秒；旧河床经转运区，公开基准二百秒，补录名单增加二十秒、检查增加二十五秒（只有实际办理才清除待办）。

**作者分支。** A：主桥允许车辆通行，完成 R06、R07 抵达接收站。B：申请二十秒后遭到明确拒绝；玩家仍在同一关，报告和上传额度不补满。旧建议失效，可做一次改道恢复选择，或继续等待。旧河床经过 N09、N10 到达 N07。

**教学意图。** 一个模型可以准确描述看见的东西，同时仍缺少决定所需的关键事实。对建议的信任应随证据和条件调整。

## 尾声与结局

1. **抵达且沿途手续齐备。** 车门打开，接收人员开始逐一点名。最后一段路结束了，二十个人的下一段生活开始了。当前版本在抵达时封存；完整人员交接尚未实际演出，因此 handoffCompletedAtMissionMs 保持 null，不声称交接已经完成。
2. **抵达但交接待办。** 已到接收站，仍有名单或检查事项未完成。游戏清晰区分抵达成功与交接完成，不把后者自动勾选。
3. **错过窗口。** 计时到达十分钟，接收安排需要重新协调；当前位置与已发生的结果保留。不添加死亡或袭击惩罚。
4. **主动结束。** 留存到当前为止的决策和报告，可进行有限复盘；不得当作完整表现样本。
5. **技术中断。** 后端重启封存活动局，独立标记技术原因，不据此判断信任能力。

抵达恰好发生在 600,000 毫秒时按抵达优先结算。最终评价与结局并列呈现：四个行为维度可以同时有迹象，也可以证据不足；评价引用当时记录，而不因为路线幸运成功就奖励、失败就惩罚。自由填写的决策理由为自述，不伪装成已测量的心理动机。

## 视觉与交互叙事

开场用电影感暮色画面，主界面用石墨绿、沙金与低饱和薄荷色。每一幕有独立二维环境画面，标注“场景插画，非侦察影像”。三维沙盘来自现有 Blender GLB，用公开路网驱动车队位置；二维路线图可随时切换，WebGL 不可用时自动回退。前端只含公开叙事和静态地图，私有双剧本与来源真相不进入构建。

调查面板、报告阅读、上传选择和 AI 引用均使用实际服务返回的数据。所有正式行动先展示公开耗时与风险，允许记录理由和引用；玩家可在 AI 分析完成前自行决策。场景切换保留整局资源压力，终局提供逐条回看与 JSON 导出。
