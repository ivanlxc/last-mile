# 无限时长试玩版

2026-09-19，本地实验分支 `codex/gesture-map-experiment` 的独立规则迭代。Git 标签为 `checkpoint/game-05-unlimited-time`，上一版手势检查点为 `checkpoint/gesture-04-thumb-up`。本次不改 Unity 引擎或手势输入，也未推送 GitHub。

## 当前行为

- 新局没有总时间上限。右上角及弹窗显示累计用时，不再倒数或随剩余时间变红。
- 超过十分钟仍可调查、下令、行驶并正常抵达。原八分钟医疗催促取消，乘员保持稳定等待转送。
- 调查、等待、行驶继续使用真实耗时；并行岗位、调查额度、离场取消和车辆运动语义不变。
- 用时保留在复盘和导出中，尚未新增数值总分、效率奖励或时间扣分。
- 新局政策版本为 `0.6.0`；已有历史仍保留原政策、内容版本、时限和封存结果，不重算旧成绩。

## 实现与边界

`missionDeadlineMs: null` 明确表示无限。新会话把这个值保存到私有状态，旧快照缺少该字段时仍解释为原来的 600000ms。`missionTimeMs` 不再在十分钟截断；调度器没有待处理事件时正常返回。到达判定不再附加新局的十分钟条件。

政策中的医疗目标也为 `null`，因此不会生成八分钟的状态变化或催促。内部启动事件记录实际的 deadline 与 startedAt；公共契约与生成类型可读取新局的 null 和旧局的数值。Projection 和终局 seal 从原会话读取 policy/content 绑定，避免规则升级后改写历史含义或违反数据库的封存约束。

有调查或车辆行动时继续每秒发布带位置的 `clock.sample`。静止阅读、没有待处理行动时不再每秒追加不可变日志；浏览器根据最近的服务器样本和单调时钟显示累计用时，刷新时重新同步，游戏命令始终由后端时间结算。

“无限时长”不包含跨服务重启续玩：当前停止服务仍会把活动局封存为技术中断；页面刷新不会结束任务。云端容量限制、模型调用预算与技术超时保持现有规则。

## 本地试用与回滚

打开 http://127.0.0.1:5173/ ，刷新并新开一局即可使用新规则。旧局已经封存的结果不会自动变成无限局。Unity、点赞切换和平移/旋转/缩放继续可用。

修改前已通过 SQLite backup API 保存本机试用库快照至 Git 忽略的 `.local-artifacts/checkpoints/pre-unlimited-20260919-113331.sqlite`，没有复制正在写入的单独主库文件或覆盖原数据库。

需要比较上一版本时，先停止开发服务并确认工作区干净，再从已保存标签创建新分支：

```sh
git switch -c codex/compare-timed checkpoint/gesture-04-thumb-up
pnpm install --frozen-lockfile
pnpm build
MODEL_PROVIDER=offline LAST_MILE_DB=.last-mile/timed-comparison.sqlite pnpm dev
```

比较时使用独立数据库，避免混用不同规则的活动局。本次前后 Unity 源码相同，已存在的同版 Unity Web 产物可以复用；若构建产物缺失则先执行 `pnpm build:unity`。回到当前实验使用 `git switch codex/gesture-map-experiment` 并重建前端、恢复原试用库启动命令。
