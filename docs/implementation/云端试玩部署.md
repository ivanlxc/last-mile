# LAST MILE · Render Free + Neon Free 试玩部署

更新：2026-09-16。适用：团队和评委定向分享，1–5 人同时各自进行单人游戏。本文替代早期付费磁盘方案。代码候选与本机测试不等于云端已经发布；发布记录见文末。

## 1. 选择与费用

- 应用：Render **Free Web Service**，Node 24，单实例；网页、API、事件流同域。
- 数据库：Neon **Free PostgreSQL**，独立于 Render 文件系统保存。
- AI：服务器调用 OpenAI；试玩者无需 API key。模型费用记在配置密钥的供应商账户，与基础托管分开。
- 无需 Docker 镜像。Render 从 GitHub 安装依赖、构建并运行 Node 服务。

Render Free 会在闲置后休眠，首次访问可能等待约一分钟，临时磁盘不保存跨重启数据；因此不把游戏数据库放在 Render 本地。免费额度耗尽会影响可用性。只选择 Free、不启用付费资源或额外付费选项。[Render Free](https://render.com/docs/free)

Neon Free 也有容量、计算和流量额度；创建时确认选中 Free，关注控制台用量。账户操作和套餐确认由项目所有者完成。[Neon plans](https://neon.com/pricing)

## 2. 先创建 Neon

1. 打开 [Neon](https://console.neon.tech/)，注册或登录。
2. 创建项目 `last-mile`，选择 **Free**；选择靠近 Render Ohio 的美国东部区域。
3. 保留默认数据库、角色即可。不要运行仓库中 SQLite 的 `001_initial.sql`：程序会执行 PostgreSQL 专用迁移。
4. 打开项目的 **Connect** 面板，选择正确的数据库与角色。
5. **关闭 Connection pooling**，复制直接连接的 PostgreSQL URL。地址中的主机名不应包含 `-pooler`。本实现使用会话锁保证同一数据库只有一个游戏引擎，不能经过事务连接池。
6. 把完整连接字符串填入 Render 的 `DATABASE_URL`。保留 TLS 参数；不要把它发到聊天、GitHub 或客户端代码中。

连接字符串形如 `postgresql://角色:密码@主机/数据库?sslmode=require`。这是格式说明，不是可用凭据。

## 3. Render 创建页面逐项填写

| 字段 | 值 |
|---|---|
| 类型 | Web Service |
| Repository | `ivanlxc/last-mile` |
| Name | `last-mile` |
| Language | Node |
| Branch | `main` |
| Region | Ohio |
| Root Directory | 留空 |
| Build Command | `pnpm install --frozen-lockfile --prod=false && pnpm build` |
| Start Command | `pnpm run start` |
| Compute | **Free / $0** |
| Advanced → Health Check Path | `/_platform/health` |
| Auto Deploy | 首轮设为 Off，验证后手动部署 |

`pnpm start` 和 `pnpm run start` 都运行 `package.json` 的 `scripts.start`，本项目两者等价。这里统一使用完整写法，避免来回改动。[pnpm start](https://pnpm.io/cli/start)

构建需要开发依赖（TypeScript/Vite），当前启动入口也用到 `tsx`，因此安装命令保留 `--prod=false`。这是构建工具安装方式，与模型 provider 无关。

仓库根目录 `render.yaml` 也提供同样配置，可用于 Blueprint；已经打开手工 Web Service 创建页面就继续手工填写，不必另建第二个同名服务。Blueprint 明确指定 `plan: free`，不创建 Render 数据库或磁盘。[Render Blueprint](https://render.com/docs/blueprint-spec)

## 4. Environment Variables

公开空模板：`deploy/render.env.example`。**在 Render 环境变量中填真实值，不修改这个公开模板。** 本地 `.env` 被 Git 忽略，所以 GitHub 部署不会自动获得本机密钥。

### 必填运行配置

```dotenv
NODE_VERSION=24
NODE_ENV=production
LAST_MILE_MODE=cloud
MODEL_PROVIDER=openai
OPENAI_MODEL=gpt-5.6-luna
OPENAI_REASONING_EFFORT=low
AI_ADVISOR_TIMEOUT_MS=30000
AI_EVALUATOR_TIMEOUT_MS=45000
AI_ADVISOR_MAX_OUTPUT_TOKENS=2500
AI_EVALUATOR_MAX_OUTPUT_TOKENS=5000
LAST_MILE_MAX_ACTIVE_SESSIONS=5
LAST_MILE_MAX_SESSIONS_PER_PLAYER_PER_DAY=3
AI_MAX_DAILY_ATTEMPTS=100
AI_MAX_CONCURRENT_JOBS=2
```

### 四项秘密值

| 变量 | 填什么 | 谁能看到 |
|---|---|---|
| `DATABASE_URL` | Neon 直接连接地址，含密码 | 仅项目管理者和服务器 |
| `OPENAI_API_KEY` | 已在本机验证的 OpenAI key | 仅项目管理者和服务器 |
| `LAST_MILE_INVITE_CODE` | 至少 16 字符；可点 Render 的 Generate | 管理者及获邀试玩者 |
| `LAST_MILE_COOKIE_SECRET` | 至少 32 字符；可点 Generate | 仅项目管理者和服务器 |

邀请口令和 cookie secret 是两个不同值，不要把 API key 当作邀请口令。Cookie secret 在后续部署间保持不变。

Render 自动提供 `PORT` 和 `RENDER_EXTERNAL_URL`，无需照抄本地的 `PORT=3111`。若未来使用自定义域名，再显式设置 `LAST_MILE_PUBLIC_ORIGIN=https://精确域名`。

`MODEL_PROVIDER=offline` **不会访问模型**，仅适用于本机无费用开发测试。云端入口要求选择真实 provider 并配置 key/model，避免误将离线演示发布为真实 AI 游戏。运行中模型出错仍会明确标出模板回退，不能把模板卡片当作真实回答。

## 5. 发布与验收

1. 确认 GitHub 的部署候选已通过构建、SQLite/PostgreSQL 与访问隔离测试。
2. 在 Render 填完环境变量后点击 Deploy Web Service。
3. 等待构建成功、日志显示云端监听、健康检查通过。首次运行自动迁移**专用**数据库，部署过程中不要启动第二个连接同库的游戏引擎。
4. 用真实 HTTPS 地址打开页面。输入邀请口令；新浏览器默认 English，可切中文。
5. 开始新局，进入首个决策场景，确认 AI 顾问显示 `LIVE MODEL`。实际调用会产生模型费用。
6. 再用另一个浏览器/无痕窗口输入同一邀请口令：应得到独立玩家身份，不能看到第一个浏览器的存档。
7. 跑完一局并请求评价，确认评价也是真实模型结果；核对双语与引用质量。
8. 在没有正在试玩的玩家时做一次重启检查：原浏览器仍能打开自己的历史记录。
9. 分享 **游戏 URL＋邀请口令**。不分享 `.env`、数据库地址、API key 或 cookie secret。

如启动报错，先核对失败的变量名、迁移结果和服务日志；不要把含密钥的环境页面截图公开。

## 6. 本轮运行边界

- 每位玩家有自己的浏览器凭据。同一邀请口令只控制准入，不代表共用存档身份。
- 身份不跨设备自动同步；清除 cookie、过期或换浏览器后，原身份不会凭邀请口令自动找回。
- 云端依然是**每人单人游戏**；不是多人联机协作。
- 简报创建后若超过 15 分钟仍未启动，系统会在下一次准入检查时封存该局并释放名额；这属于系统中断，不会记为玩家主动放弃。
- 全站最多 5 个尚未结束的游戏、每位玩家每日最多 3 局；模型最多同时 2 个任务、每日 100 次实际发送（按 UTC 日，修复尝试和失败发送也计数）。次数上限不是美元账单硬上限；令牌用量和具体模型价格决定费用。
- 页面刷新不会重置规则额度。数据库事务在接收操作、扣调查额度、写事件及保存状态时保持一致。
- 服务器重启或被平台回收时，未完成的游戏会标为技术中断；已提交记录保留，不伪装成仍在继续。恢复后可查看历史、进行允许的评价和导出，再开新局。
- 单实例架构：数据库锁防止两个引擎同时推进游戏。首轮不要设置多个副本、自动扩容或在另一个服务中共用生产数据库。
- Free 平台的休眠、限额和可用性仍然存在。数据库持久化不等于永不间断运行。

平台健康路径 `/_platform/health` 确认进程可接收请求；游戏就绪路径为 `/api/v1/health`。两者不主动查询或唤醒休眠数据库。闲置连接失效可在下一次请求时重连；实际数据库操作失败且提交结果不确定时，引擎停止，进程退出，由平台重新启动并进行中断恢复。

## 7. 变更与维护

代码、SQL、公开模板可提交 GitHub；真实凭据、`.last-mile/`、`.local-artifacts/`、数据库备份均不得提交。

Render 的滚动替换会先启动新实例。若旧实例仍持有引擎锁，新实例进入最多 180 秒的交接等待，平台健康返回 `handoff`，游戏 API 返回 503，页面显示自动刷新的等待页；旧实例退出并释放锁后，新实例才初始化、恢复记录并接管游戏。整个过程中只有一个引擎可以写入游戏状态。首次部署遇到错误数据库凭据会直接失败，不会冒充交接等待。真实 Render 切流、停旧实例的具体时序仍需线上验收。

试玩期间关闭自动部署，安排无人游戏时再发布。更换模型密钥后保存环境变量并重新部署；更改邀请口令影响新准入，已有玩家身份的撤销另行处理。更换 cookie secret 会使现有签名失效，务必事先安排。

先保留旧部署版本与数据库备份，再回滚代码；不要通过清库“修复”迁移问题。PostgreSQL 迁移与 SQLite 迁移分开，云端不自动上传开发机历史存档。
