# 手势控制实验与回滚

这是供真人试用的独立实验，不代表已决定纳入正式产品。分支为 `codex/gesture-map-experiment`，`main` 保持 Blender + Unity 稳定版。摄像头默认关闭，开启状态不会保存到浏览器存储。

## 本机试用

打开 http://127.0.0.1:5173 ，刷新后进入简报，选择 **Unity → 手势 · 试用 → 启用摄像头**。英文入口是 **Unity → Gestures · try it → Enable camera**。打开面板会自动展开地图。浏览器首次使用时需要你允许摄像头权限。

1. 将张开的手放在镜头前，确认预览中出现手部骨架。
2. **选模式**：默认平移。单手比 V（食指、中指伸直分开，无名指和小指收起）保持 0.7 秒，依次切换 **平移 → 旋转 → 缩放 → 平移**。每次保持只切一次；先收起 V、张手片刻，再捏合或再次比 V。也可以点击面板的三个模式按钮。
3. **单手平移**：在平移模式下，拇指与食指捏合，保持约 100 毫秒，移动手掌。画面按镜像预览的方向拖动。
4. **单手旋转**：在旋转模式下，用同样的捏合手势，左右移动改变偏航，上下移动调整俯仰；不会增加画面侧倾。
5. **单手缩放**：在缩放模式下，捏合后向上移动放大、向下移动缩小；横向移动不产生缩放。完全不需要第二只手。
6. 松手立即停止。切换模式、手离开画面、出现第二只手或使用鼠标后，先张手再重新捏合。选中的模式会保留，旧的运动位移不会带入下一次抓取。
7. 调节灵敏度（0.5–1.8×）。有多个摄像头时先关闭摄像头，再选择设备并重新开启。
8. 按 **Esc**、关闭面板、点击“关闭摄像头”、切换到二维/原三维地图，都会释放摄像头。切到后台标签页也会关闭；回到页面需主动重启。

鼠标平移、右键旋转、滚轮缩放、Home 全景与 F 跟随车队继续可用。平移和旋转会退出跟随，缩放保留跟随目标。任务中使用手势不会暂停任务计时，车队继续按后端进度行驶。

开发服务重开命令（使用既有试用库，不修改 `.env`）：

```bash
MODEL_PROVIDER=offline LAST_MILE_DB=.last-mile/unity-preview.sqlite pnpm dev
```

## 实现

`摄像头 → CameraRuntime → Web Worker / MediaPipe → GestureInterpreter → ApplyCameraInput → Unity MapCamera`

- `@mediapipe/tasks-vision` 固定为 **1.0.1**；使用 Hand Landmarker float16 v1。模型最多检测两只手，以便发现第二只手时暂停控制；交互层仅允许一只手，不支持双手操作。
- 模型在 `assets/models/mediapipe/`，来源、SHA-256 和许可证随仓库保存。`pnpm prepare:gestures` 校验模型并将模型与已安装包中的 WASM/JS 复制到 `client/public/gestures/`。`pnpm dev`、`pnpm dev:client` 和 `pnpm build` 自动执行此步骤；运行时无需 CDN。
- 640×480 摄像头目标尺寸；推理在 module Worker 中执行，CPU delegate，最多 25 Hz、同一时刻仅一帧在途。传输完成后关闭 ImageBitmap；超过 250ms 的结果丢弃。冷启动最多等 30 秒，单帧无响应 3 秒后停止并释放。帧不新鲜时清空骨架并要求重新张手。
- 识别器输出未经镜像的坐标，交互层只镜像一次 X。捏合使用掌长归一化距离及 0.38/0.58 进入/退出阈值，100ms 时间防抖和 45ms 低通平滑；距离按图像宽高比修正。平移、旋转使用同一单手位移，缩放仅使用竖直位移的 3 倍作为对数缩放增量。
- 手势模式与抓取状态分离：模式在暂停、丢手和鼠标接管后保留；抓取锚点清空。V 持续 700ms 才切换模式，计时期间不移动地图；保持 V 不连续循环。手势或按钮切换都必须重新张手再抓取。
- 跟踪丢失、过长帧间隔、第二只手或位置瞬移会释放当前抓取；模式切换重新锚定，避免镜头跳跃。
- Unity 的 `orbit` 接口把归一化横向位移映射为偏航、竖直位移映射为俯仰，俯仰限制 16–78°，不引入 roll。缩放和平移保持现有限位。
- `ApplyCameraInput` 和游戏的 `ApplyRenderState` 使用各自独立的序列号。C# 校验实例、递增序号、模式与有限数值范围；此接口只能移动相机，不调用游戏命令或变更车队位置。
- 鼠标按键/滚轮/键盘操作优先；浏览器端重新张手才能恢复。视频、骨架和识别结果只保存在当前浏览器内存中，不录制、不上传，也不提供给游戏的 AI 顾问。
- 保留现有生产 CSP，无需 `unsafe-eval`、外部脚本域或外部模型域。

生成全套可部署资源的顺序：

```bash
pnpm install --frozen-lockfile
pnpm build:unity
pnpm build
```

Unity Web 构建与复制出的手势资源仍是 Git 忽略的产物；只切换 Git 提交不会自动替换 Unity 二进制。模型源文件和 pnpm lockfile 随提交保存，可重新生成资源。

## 验证与试用边界

2026-09-19 单手迭代已完成真实 Unity Web 构建、TypeScript/Vite 生产构建和单元测试。现有 31 项手势解释器测试与 9 项摄像头生命周期测试；全量 Vitest **341 通过、21 跳过**（PostgreSQL 环境未配置）。

本次重跑手势及 Unity 相关浏览器测试 **7/7 通过**，包括真实车队行驶、停车、地点选择、键盘和画布生命周期。手势测试涵盖默认关闭与显式启用；真实 MediaPipe Worker 与真实 Unity 同时运行；进入任务后时钟继续推进；Esc/切换地图释放轨道；权限拒绝后可继续游戏；单手确定性关键点通过 V 切换模式后使真实 Unity 平移、旋转和缩放；持续 V 只切换一次；出现第二只手即停止且仍捏合时不能直接续接；按钮切换也需重新抓取。最后一个测试只替换识别结果，不替换解释器、桥接或 Unity，引擎画面比较排除动态摄像头预览。此前检查点 02 的完整浏览器套件为 13/13 通过。

未变更的生产打包 Worker 已在与服务端完全相同的 CSP 下验证真实推理：无 CSP 违规、无外部请求、无帧上传，退出后轨道为 ended。模拟摄像头的 5 帧样本中冷启动推理约 77ms，随后约 19–24ms；这只是本机小样本，不是识别性能承诺。

自动验证使用 Chrome **模拟摄像头**，没有启用使用者的真实摄像头。真人手型、光照、遮挡、镜头位置与持续操作的舒适度仍需试用。建议分别试 30 秒单手平移、旋转、缩放，以及 V 切换、松手/移出镜头、鼠标接管，再在车队行驶时重复。面板显示实际处理帧率、推理耗时和识别手数，便于反馈。

回到实验前：先停止开发服务，确认 `git status` 没有未保存修改，然后执行：

```bash
git switch main
pnpm install --frozen-lockfile
pnpm build:unity
pnpm build
MODEL_PROVIDER=offline LAST_MILE_DB=.last-mile/unity-preview.sqlite pnpm dev
```

这里的 `main` 当前指向 `fbcec2b`。如果以后 `main` 已前进，可从稳定标签开新分支重现：`git switch -c codex/restore-pre-gesture checkpoint/pre-gesture-20260918`，随后执行同样安装、构建步骤。不要用 `git reset --hard` 或删除实验分支来回滚。

回到本实验可用 `git switch codex/gesture-map-experiment`，安装依赖并重新构建 Unity 与前端。若希望从某次迭代另开路线，用 `git switch -c codex/gesture-alternative checkpoint/gesture-03-single-hand`；将最后的标签改为 `checkpoint/gesture-02-local-preview` 可重现旧的双手版本。停止/重启游戏服务可能封存活动中的对局，验证版本时建议新建试用局。
