# 手势控制实验与回滚

这是供真人试用的独立实验，不代表已决定纳入正式产品。分支为 `codex/gesture-map-experiment`，`main` 保持 Blender + Unity 稳定版。摄像头默认关闭，开启状态不会保存到浏览器存储。

## 本机试用

打开 http://127.0.0.1:5173 ，刷新后进入简报，选择 **Unity → 手势 · 试用 → 启用摄像头**。英文入口是 **Unity → Gestures · try it → Enable camera**。打开面板会自动展开地图。浏览器首次使用时需要你允许摄像头权限。

1. 将张开的手放在镜头前，确认预览中出现手部骨架。
2. **单手平移**：拇指与食指捏合，保持约 100 毫秒，移动手掌。画面按镜像预览的方向拖动。
3. **双手缩放**：两手分别捏合，拉开放大、靠拢缩小；不同时叠加平移。
4. 松手立即停止。手离开画面、双手交叉、从双手变单手或用鼠标操作后，先张手再重新捏合。
5. 调节灵敏度（0.5–1.8×）。有多个摄像头时先关闭摄像头，再选择设备并重新开启。
6. 按 **Esc**、关闭面板、点击“关闭摄像头”、切换到二维/原三维地图，都会释放摄像头。切到后台标签页也会关闭；回到页面需主动重启。

鼠标平移、右键旋转、滚轮缩放、Home 全景与 F 跟随车队继续可用。首版手势提供平移和缩放；旋转仍使用右键。平移会退出跟随，缩放保留跟随目标。任务中使用手势不会暂停任务计时，车队继续按后端进度行驶。

开发服务重开命令（使用既有试用库，不修改 `.env`）：

```bash
MODEL_PROVIDER=offline LAST_MILE_DB=.last-mile/unity-preview.sqlite pnpm dev
```

## 实现

`摄像头 → CameraRuntime → Web Worker / MediaPipe → GestureInterpreter → ApplyCameraInput → Unity MapCamera`

- `@mediapipe/tasks-vision` 固定为 **1.0.1**；使用 Hand Landmarker float16 v1，最多跟踪两只手。
- 模型在 `assets/models/mediapipe/`，来源、SHA-256 和许可证随仓库保存。`pnpm prepare:gestures` 校验模型并将模型与已安装包中的 WASM/JS 复制到 `client/public/gestures/`。`pnpm dev`、`pnpm dev:client` 和 `pnpm build` 自动执行此步骤；运行时无需 CDN。
- 640×480 摄像头目标尺寸；推理在 module Worker 中执行，CPU delegate，最多 25 Hz、同一时刻仅一帧在途。传输完成后关闭 ImageBitmap；超过 250ms 的结果丢弃。冷启动最多等 30 秒，单帧无响应 3 秒后停止并释放。帧不新鲜时清空骨架并要求重新张手。
- 识别器输出未经镜像的坐标，交互层只镜像一次 X。捏合使用掌长归一化距离及 0.38/0.58 进入/退出阈值，100ms 时间防抖和 45ms 低通平滑。双手距离按画面宽高比修正，不使用每只手独立原点的 world landmarks 计算手间距离。
- 几何身份匹配避免关键点数组换序后控制权互换。跟踪丢失、过长帧间隔、交叉歧义或瞬移会释放当前抓取；模式切换重新锚定，避免镜头跳跃。
- `ApplyCameraInput` 和游戏的 `ApplyRenderState` 使用各自独立的序列号。C# 校验实例、递增序号、模式与有限数值范围；此接口只能移动相机，不调用游戏命令或变更车队位置。
- 鼠标按键/滚轮/键盘操作优先；浏览器端重新张手才能恢复。视频、骨架和识别结果只保存在当前浏览器内存中，不录制、不上传，也不提供给游戏的 AI 顾问。
- 保留现有生产 CSP，无需 `unsafe-eval`、外部脚本域或外部模型域。

生成全套可部署资源的顺序：

```bash
pnpm install --frozen-lockfile
pnpm build:unity
pnpm build
```

Unity Web 构建与复制出的手势资源仍是 Git 忽略的产物；只切换 Git 提交不会自动替换 Unity 二进制。模型源文件和 pnpm lockfile 随提交保存，可重新生成资源。

## 验证与试用边界

2026-09-19 已完成真实 Unity Web 构建、TypeScript/Vite 生产构建和单元测试。新增 28 项手势解释器测试与 9 项摄像头生命周期测试；全量 Vitest **338 通过、21 跳过**（PostgreSQL 环境未配置）。

全量浏览器测试 **13/13 通过**，包括原有完整游戏流程与真实车队行驶、停车。新增测试涵盖：默认关闭与显式启用；真实 MediaPipe Worker 与真实 Unity 同时运行；进入任务后时钟继续推进；Esc/切换地图释放轨道；权限拒绝后可继续游戏；确定性关键点输入使真实 Unity 平移与缩放，丢手后停止且不能以仍捏合的手直接续接。后一个测试只替换识别结果，不替换解释器、桥接或 Unity，引擎画面比较排除动态摄像头预览。

另用生产打包后的 Worker，在与服务端完全相同的 CSP 下验证真实推理：无 CSP 违规、无外部请求、无帧上传，退出后轨道为 ended。模拟摄像头的 5 帧样本中冷启动推理约 77ms，随后约 19–24ms；这只是本机小样本，不是双手识别性能承诺。

自动验证使用 Chrome **模拟摄像头**，没有启用使用者的真实摄像头。真人手型、光照、遮挡、镜头位置与持续操作的舒适度仍需试用。建议分别试 30 秒平移、双手缩放、松手/移出镜头、鼠标接管，再在车队行驶时重复。面板显示实际处理帧率、推理耗时和识别手数，便于反馈。

## Git 检查点与回滚

所有检查点通过普通提交和附注标签保留，不重写历史：

| 标签 | 内容 |
| --- | --- |
| `checkpoint/pre-gesture-20260918` | 稳定基线，提交 `fbcec2b`，与开始实验时的 `main` 相同 |
| `checkpoint/gesture-01-camera-input` | 第一阶段，提交 `9525421`：手势状态机与 Unity 相机接口 |
| `checkpoint/gesture-02-local-preview` | 完整可试用实验：摄像头、真实模型、面板、集成测试和此文档 |

查看历史：

```bash
git log --oneline --decorate -8
git tag --list 'checkpoint/*'
```

回到实验前：先停止开发服务，确认 `git status` 没有未保存修改，然后执行：

```bash
git switch main
pnpm install --frozen-lockfile
pnpm build:unity
pnpm build
MODEL_PROVIDER=offline LAST_MILE_DB=.last-mile/unity-preview.sqlite pnpm dev
```

这里的 `main` 当前指向 `fbcec2b`。如果以后 `main` 已前进，可从稳定标签开新分支重现：`git switch -c codex/restore-pre-gesture checkpoint/pre-gesture-20260918`，随后执行同样安装、构建步骤。不要用 `git reset --hard` 或删除实验分支来回滚。

回到本实验可用 `git switch codex/gesture-map-experiment`，安装依赖并重新构建 Unity 与前端。若希望从某次迭代另开路线，用 `git switch -c codex/gesture-alternative checkpoint/gesture-02-local-preview`。停止/重启游戏服务可能封存活动中的对局，验证版本时建议新建试用局。
