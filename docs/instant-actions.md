# 即时行动：剧情耗时与真实游玩用时

取消总倒计时后，原来的任务队列仍按单调现实时间等待报告和行驶结束。例如西门主路的 65 秒成本会让玩家实际等待至少 65 秒。新任务默认采用即时结算，将这类剧情耗时留在模拟规则中，移除人为等待。

## 玩家行为

| 行为 | 现在的反馈 | 时间记录 |
| --- | --- | --- |
| 开始护送 | 直接到第一关 | R00 的 30 秒计入剧情时间 |
| 索取已有简报、调查、溯源或更正 | 交付并展开报告 | 累计作者定义的模拟耗时，额度照常扣除 |
| 选择路线 | 立即处理沿途规则、显示结果并更新位置/关卡 | 累计该路线实际发生的模拟行驶与停留时间 |
| Advance time | 立即推进所选时长，停留在当前地点 | 累计 15、30 或 60 秒剧情时间 |
| 阅读、思考、地图交互 | 自由操作 | 仅实际游玩用时增加 |
| AI、语音 | 显示真实请求的处理状态 | 不把模拟时间跳跃用于网络超时 |

报告自动展开不等于自动上传给 AI。阅读回执仍依赖卡片实际可见；正式上传仍由玩家选择。请求失败保留窗口与错误提示，成功时返回已完成的任务/行动；客户端继续使用幂等请求键避免重复扣费。

## 实现

- `State.actionTiming` 随每局持久化，新建默认 `instant`。历史缺少该字段的快照保留旧解释，测试可在进程内显式设置 `realtime`，没有公开的 HTTP 调速入口。
- `missionTimeMs` 是剧情时间。即时模式下读取、轮询和服务器 tick 都不会使其随现实时间增加。
- 接受开始/任务/行动后，在同一命令事务内处理已接受工作范围中的事件，沿用原来的排序和路线规则。各次状态保存保留数据库「单次版本增量不超过 1」约束；完成响应、扣费、报告和结果一起提交，失败整体回滚。
- `playerElapsedMs` 是开始护送后的真实用时，由服务器单调时钟计算。Projection 与 SSE 提供样本，终局保存最终值；前端可插值显示，服务器仍是记录来源。
- 模拟时间与真实用时均不向 AI 自动公开。AI 工作队列继续使用现实时间的截止时刻，调查即时完成也不会等 AI 生成结束。
- 意外退出时恢复使用最近保存的真实用时样本，不把停机期间算作游玩；现有「重启封存未完成任务」规则仍保留，不新增暂停续玩。
- 新字段在公共契约中是可选字段，旧历史记录仍可验证和打开；不重写历史封存哈希。

地图继续消费服务器的公开车队位置。当前即时结算会直接更新到行动结束的位置，不提供持续数分钟的行驶动画，也不向地图发送隐藏路线计划。
