# 参考资料与采用范围

查阅日期：2026-09-16。只引用公开的一手资料；不存在一个所有FAANG团队通用且强制的PRD/HLD/LLD模板。本包采用可审查边界、可运行契约、故障策略与证据化验收，不声称取得内部标准或认证。

| 一手资料 | 本设计采用 | 不作的推断 |
|---|---|---|
| [Google代码评审关注项](https://google.github.io/eng-practices/review/reviewer/looking-for.html) | 设计、正确性、复杂度、测试、文档一起审阅 | 不是Google官方游戏PRD模板 |
| [Microsoft Azure REST API Guidelines](https://github.com/microsoft/api-guidelines/blob/vNext/azure/Guidelines.md) | 幂等重试、异步operation、明确错误与兼容性 | 本地游戏未宣称实现所有Azure规则 |
| [OpenAPI 3.1.1](https://spec.openapis.org/oas/v3.1.1.html) | 锁定版本的机器可读API合同 | 不称其为最新版本 |
| [C4图层](https://c4model.com/diagrams) | context/container/component/dynamic分层阅读 | 不要求为了画图采用微服务 |
| [draw.io文件格式](https://www.drawio.com/docs/manual/editor/save-file-formats/) | 原生XML可编辑源与导出预览 | PNG本身不能代替源图 |
| [draw.io Desktop官方仓库](https://github.com/jgraph/drawio-desktop) | 官方31.4.5应用实际导出PNG/SVG | 没有改装或假装使用StarUML |
| [Node官方版本周期](https://nodejs.org/en/about/previous-releases) | 参考Node24 LTS，实施时固定依赖锁 | 未安装/构建完整游戏栈 |
| [Fastify验证/序列化](https://fastify.dev/docs/latest/Reference/Validation-and-Serialization/) | 入参和响应Schema边界；只载入可信Schema | Schema通过不代表业务安全已证明 |
| [SQLite事务](https://www.sqlite.org/lang_transaction.html) | 短事务、单写者、显式提交回滚 | 不声称多节点高可用 |
| [Three.js GLTFLoader](https://threejs.org/docs/pages/GLTFLoader.html) | 加载已有GLB并把渲染与状态分开 | 未用静态面数证明运行帧率 |
| [赛事页面](https://www.indienomicon.org/defensetechjam) | 用户给定比赛背景，保留48小时型演示规划 | 预制资产/代码/模型服务的具体许可仍需最终规则 |

用户来源：sources/CORE_GAMEPLAY.md是原文快照；其中“核心玩法已锁定”等文本属于来源文件立场，不能自动覆盖用户在对话中明确的单人及额度确认。原文件SHA-256记录在asset-manifest.json。

本包中的四维行为规则为游戏可观察行为提案，不是临床测评或经验证的心理量表。程序能保证引用/机会/时点约束，不足以证明学习效果或自然语言解释永远正确。
